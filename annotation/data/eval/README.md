# 标注集说明

## 文件

| 文件 | 给谁 | 什么时候用 |
|---|---|---|
| `to_label.csv` | **三位标注员** | 现在 —— 每人独立标一份 |
| `to_label_meta.csv` | 统筹 / 下游组 | **标注全部完成之后**，按 `id` join 回来做分析 |

## ⚠️ 标注前必读：为什么 to_label.csv 里没有航司和评分

手册第 16 节原来的示例代码会把 `overall_rating`、`r_seat` 这些评分列一起导给标注员。
**这样做会毁掉评测**，原因如下：

训练用的弱标签正是从这些评分推出来的（4–5 星 → positive，1–2 星 → negative）。
标注员一旦看到「这条评论总分给了 9」，判断就会被锚定，于是：

```
人工金标准  ←被评分影响→  弱标签  ←推出→  分类器
```

金标准和被评测的对象共享同一个信息源，**等于自己出题自己考**，
算出来的 P/R/F1 会系统性偏高，而且这个偏差在报告里没法辩护。

所以 `to_label.csv` 里**只有句子本身**。请**只看句子做判断**，不要去猜它来自哪家航司。

## 怎么标

打开 `to_label.csv`（Excel 能直接开，已加 BOM 不会乱码），填后面四列：

| 列 | 取值 | 说明 |
|---|---|---|
| `subjectivity` | `objective` / `subjective` | 陈述事实 还是 表达观点 |
| `polarity` | `positive` / `negative` / `NA` | **只有 subjective 才填**；objective 一律填 `NA` |
| `aspect` | `seat` `staff` `food` `entertainment` `ground` `value` `overall` `other` | 这句在讲哪个方面 |
| `note` | 自由填写 | 拿不准的写原因，例如 `sarcasm`、`两个方面都有` |

**判定规则和边界情况**见 `docs/选题与标注方案.md` 第 7–9 节，标之前先读一遍。

### Step 2 试标对齐不能跳

正式开标之前，三个人**各标同样的前 50 条**，碰一次头对齐标准。
花 30 分钟统一口径，比标完 1,000 条才发现一致率不达标、全部重来划算得多。

## 这 1,000 句是怎么抽的

`python scripts/make_eval_set.py` 生成，可复现（seed=42）。

从 546,139 句里筛：

| 步骤 | 剔除 |
|---|---|
| 排除纯航线元数据（`is_route_only`） | −16,772 |
| 排除重复句（`dup_count > 1`） | −14,282 |
| 排除 < 5 词的短句 | −22,294 |
| 排除无总体评分 | −13,822 |
| **候选池** | **478,969** |

然后：

- **按总体评分分层**：≥7 偏正面 / ≤4 偏负面，**各 500 句**（5–6 分丢弃）
- **六个维度各 120 句**（按关键词粗配平），另有 280 句不明确属于任何维度——
  这个比例接近真实分布，分类器必须能处理"哪个维度都不是"的句子
- **打乱顺序**，避免标注员形成心理惯性

实际结果：**1,000 句，来自 992 条不同评论、76 家航司，文本无重复**。

## 标注完成之后

1. 三份合并，算一致率和 Kappa（`docs/选题与标注方案.md` 第 11 节）
2. 不一致的条目全组仲裁
3. 按 `id` join 上 `to_label_meta.csv`
4. 导出 `eval.xls`——**前两列必须是 `text` 和 `label`**（作业硬性要求，格式不对扣分）
   `label` 是三分类：`objective` / `positive` / `negative`

# 双语标注系统（Claude 设计实现）

设计来源：https://claude.ai/code/artifact/ad512297-5d91-430c-830b-f77473095e03

入口为 `app/annotate.py`，不再使用仓库外的 HTML 演示版。三人独立标同一套 1,000 句，使用固定顺序的 `data/eval/to_label.csv`。只导入原文、译文、风险提示和顺序，不读取 `to_label_meta.csv`。

## 本机启动

当前机器已安装依赖、导入全部语料并创建账号。日后可双击 `scripts/启动标注系统.cmd`，再打开 http://127.0.0.1:8517 。保持启动窗口运行；如果已有服务在运行，直接打开地址即可。

在仓库根目录运行：

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-annot.txt
.venv/Scripts/python.exe scripts/init_annot_db.py --storage local --generate-passwords
$env:STORAGE = 'local'
$env:ANNOT_CACHE_DIR = "$PWD/outputs/annotation-cache"
.venv/Scripts/python.exe -m streamlit run app/annotate.py --server.address 127.0.0.1
```

如果已有 `.streamlit/secrets.toml`，省略 `--generate-passwords`。初始化会保留已有标注；发现 ID、原文或顺序变化会拒绝覆盖。三个随机密码保存于忽略的 `outputs/annotation-credentials.txt`，通过线下渠道分别给本人。bcrypt 哈希存入 secrets 并在初始化时写入 annotators 表；认证以 secrets 为准，更新密码后重新运行初始化同步表中副本。

本地模式的持久记录在 `outputs/annotation-local/annotations.csv`，使用文件锁、临时文件、fsync 和原子替换。云端应用服务器上的本地 CSV 不等于三人的本机副本。请每天导出。

## 操作

- 下拉选人并输入密码。重新登录定位本人按 seq 排序的第一条未标注句。
- 客观陈述自动设置 NA 并跳过极性；主观评价选正面或负面后再选方面。
- 按 1/2 回答当前问题；第三问按 1–8。选完方面立即 upsert 并进入下一句，没有提交／保存修改按钮。
- ←/→ 回看，载入本人原答案。改完方面再次自动保存；已完成答案的备注离开输入框时自动保存。正在保存时锁定输入。
- T 折叠中文；N 聚焦备注；Esc 退出输入；? 打开项目第 7–9 节规范。
- risk_flag 显示“注意反讽／含行话／短句”。初始化采用保守文本规则设置初始标记，可在输入表显式提供 risk_flag。它不是情感标签。
- 没有额外的待处理标签或协调员审批页面。残句、拆句等依项目规范在备注记录并线下统一处理。
- 三人先独立标前 100 句，碰头对齐后再继续；与 Claude 设计一致，不增加强制关闭批次的流程。

同一浏览器标签页用有签名、12 小时有效的会话凭据恢复登录，刷新后无需重新输入密码。修改密码会使旧凭据失效；退出清除凭据。服务端每次保存从已验证会话获取 username，不信任组件传入的身份。

## 进度与导出

看板及登录页三人进度无需登录。每 15 秒更新聚合数量、速度、预计完成日；速度采用相邻 updated_at 的间隔中位数，剔除超过 5 分钟的间隔，按每天 1 小时折算完成日期。

看板展示三人合计 objective/positive/negative 分布。某人已标至少 100 条、另外两人已有记录，且某标签占比与另两人平均相差超过 15 个百分点时提示对齐。按照提供的 Claude 设计，看板同时提供免登录的全量原始长表和三人并排宽表下载。标注页自身只收到本人答案，不发送其他人的逐句标注。

`annotations_raw.csv` 用于导出后的一致率/Kappa，`annotations_wide.csv` 用于人工仲裁。最终 eval.xls 需要人工仲裁结果，不能用未经仲裁的多数票自动冒充；前两列应为 text、label。原设计也将此步骤留在宽表导出之后。

## 缓存和恢复

每次有效保存先耐久写入 `~/.annot_cache/<user>.jsonl`，再写主存储。主存储失败显示“离线中，已缓存 N 条”，继续下一句。恢复后按原时间戳 upsert，并移除已成功补传的队列项；旧缓存不会覆盖时间更新的答案。每 15 秒重试，启动和保存时也重试。`ANNOT_CACHE_DIR` 可以更改路径，本机预览使用仓库 outputs 下路径。

缓存位于 **运行 Streamlit 的机器**，与 Claude 设计中的 `~/.annot_cache` 一致。它应对应用到数据库断连；用户浏览器完全无法连接 Streamlit 时，输入暂留当前浏览器标签页，但无法继续向服务端提交。不能将服务器磁盘称作浏览器离线数据库，也不能保证云平台重建容器后保留服务器缓存。

## 中文辅助译文

`data/eval/translations.csv` 包含 1,000 条本机生成的辅助译文。模型为 Helsinki-NLP/opus-mt-en-zh（Apache-2.0），不调用付费 API，不上传原文。机器翻译未逐条人工审核，尤其反讽、错别字和航空行话仍须以英文为准。

```powershell
.venv/Scripts/python.exe -m pip install transformers torch sentencepiece sacremoses
.venv/Scripts/python.exe scripts/translate_eval.py
.venv/Scripts/python.exe scripts/init_annot_db.py --storage local
```

脚本按 ID 断点续译，每个批次原子保存。已存在译文保持不变；需要重译时明确修订输入文件。

## Supabase + Streamlit Community Cloud

1. 创建 Supabase 项目，获取适合运行环境的 Postgres 连接串（可用 session pooler），保留 SSL。
2. 本地 `.streamlit/secrets.toml` 设置 `storage="supabase"` 和 `database_url`，保留三个 bcrypt 哈希。
3. 运行 `scripts/init_annot_db.py --storage supabase` 创建三张表并导入 1,000 句、译文与账号。
4. 在 Streamlit Community Cloud 选择仓库和分支、入口 `app/annotate.py`。把本机 secrets 内容放入该应用 Secrets，不提交 Git。
5. 三位标注员访问同一 HTTPS URL。每天下班导出 CSV 并提交到 data/eval。

`STORAGE=local` 环境变量优先于 secrets；回到 Supabase 时移除该变量或设为 supabase。两种模式界面和字段一致，但不同机器的 local CSV 不会自动跨机器共享或合并，切换前应备份。

前端 bundle 已随代码提供，Streamlit Cloud 不需要 Node。若修改组件，进入 `app/annot/frontend` 后运行 `pnpm install`、`pnpm run build`。

# 组员下载、运行与验收指南

这份指南用于把当前系统发给组员检查。组员从 GitHub 的 `main` 分支克隆后，拿到的**受 Git 管理的源码、正式 gold、评测文件、实验结果和文档**与 GitHub `main` 完全一致；本地生成的大文件不会随 Git 下载，需要按本文命令重建。

## 1. 先说明“是否和我的版本一样”

| 内容 | 克隆后是否一致 | 说明 |
|---|---:|---|
| `src/`、`app/`、`scripts/` | 是 | 分类、检索、问答和界面源码都在 Git 中 |
| `tests/` | 是 | 自动测试完整保留 |
| `data/eval/` | 是 | 包括冻结的 1,000 条 gold、`eval.xls` 和 40 题冒烟测试集 |
| `experiments/`、`report/` | 是 | 包括正式检索评测、RAG 评测和消融实验结果 |
| `requirements.txt` | 是 | 主 Python 环境的依赖清单 |
| `data/raw/` | 否 | 原始数据不进 Git，需运行下载脚本 |
| `data/processed/` | 否 | 清洗后的知识库需从原始数据重建 |
| `index/` | 否 | BM25、FAISS 和检索 ID 索引需重建 |
| `outputs/` | 否 | 分类权重、529,031 条离线标签和运行缓存需重建 |
| `models/` 和 Qwen 权重 | 否 | 模型权重体积较大，需在各自电脑下载 |
| `.venv/` | 否 | Python 虚拟环境必须在各自电脑创建 |

因此，组员会拿到同一套**可复现系统**，但刚克隆完成时不会自动拥有你电脑上已经生成好的模型、索引和缓存。只有代码审查、测试和查看既有实验结果时，不需要重建这些大文件；要在组员电脑上实际查询，才需要完成第 4～7 节。

## 2. 下载并确认处于同一版本

```bash
git clone https://github.com/ntu-ai6127-g-13/ai6127-airline-rag.git
cd ai6127-airline-rag
git switch main
git pull --ff-only origin main
git status
git log -1 --oneline
```

`git status` 应显示：

```text
On branch main
Your branch is up to date with 'origin/main'.
nothing to commit, working tree clean
```

每位组员把下面命令的输出发到群里即可核对是否处于完全相同的 Git 版本：

```bash
git rev-parse HEAD
```

如果所有人的 40 位提交编号相同，受 Git 管理的文件就是同一版本。为了检查某个固定版本，即使 `main` 后来又有新提交，也可以使用你收到的提交编号：

```bash
git fetch origin
git switch --detach <40位提交编号>
```

检查完成后回到最新版：

```bash
git switch main
git pull --ff-only origin main
```

不要用聊天软件直接传压缩包作为正式版本来源。压缩包没有提交编号，也容易遗漏隐藏文件或混入本机生成物。

## 4. 下载原始数据并重建知识库

项目使用公开的 Skytrax 航空评论数据。仓库根目录执行：

```bash
pip install kagglehub
python scripts/download_data.py
python -m src.build_kb
```

自检时应重点核对：

| 项目 | 预期值 |
|---|---:|
| 原始行数 | 131,895 |
| 有正文的评论 | 65,947 |
| 去重后评论 | 61,172 |
| 最终进入知识库 | 61,167 条评论 |
| 切分后句子 | 546,139 |
| 航司数 | 81 |
| 时间范围 | 2002-08 至 2019-06 |

如果数字明显不同，通常是下载了同名的其他数据集，或者使用了不同的原始文件。

## 5. 重建 BM25 和 FAISS 检索索引

知识库生成后执行：

```bash
python -m src.retriever build-bm25
python -m src.retriever build-dense --batch-size 64
```

第一次运行会下载 `all-MiniLM-L6-v2`。生成的主要文件位于：

```text
index/bm25.pkl
index/faiss.index
index/chunk_ids.npy
index/chunk_texts.npy
```

可以先做一个命令行检索检查：

```bash
python -m src.retriever search hybrid "seat legroom" --top-k 5
```

## 6. 重建分类权重和全量离线标签

正式 gold 只用于评测，不进入下面的弱监督训练。先生成分类权重：

```bash
python scripts/run_training_monitor.py \
  --output-dir outputs/weak_rebuild_20261019 \
  --control-dir outputs/weak_rebuild_monitor_20261019
```

Windows PowerShell 可写成一行：

```powershell
python scripts/run_training_monitor.py --output-dir outputs/weak_rebuild_20261019 --control-dir outputs/weak_rebuild_monitor_20261019
```

然后生成与检索 ID 对齐的全量标签索引：

```bash
python -m src.label_index \
  --model outputs/weak_rebuild_20261019/model.joblib \
  --output-dir outputs/label_index_20261019
```

Windows PowerShell：

```powershell
python -m src.label_index --model outputs/weak_rebuild_20261019/model.joblib --output-dir outputs/label_index_20261019
```

完成后应存在：

```text
outputs/label_index_20261019/labels.parquet
outputs/label_index_20261019/report.json
```

参考构建规模为 529,031 条基础标签。离线标签用于软排序、总体倾向统计和描述性草稿，不应当成真实人工标签。

## 7. 启动查询系统

### 7.1 不使用本地 Qwen

这种方式适合跨平台检查检索、筛选、评分、引用和程序化回答：

```bash
python scripts/run_query_app.py --port 8517
```

浏览器打开：

```text
http://127.0.0.1:8517
```

如果页面没有自动打开，手动输入上面的地址。在侧栏关闭“使用本地 Qwen 生成回答”，系统会使用确定性的有据回答。没有离线标签索引时页面仍能检索，但标签辅助排序和完整正负面汇总会受限。

### 7.2 Apple Silicon 上启用 Qwen3 4B

当前仓库的本地生成服务使用 MLX，因此这一套启动脚本仅直接支持 Apple Silicon Mac。首次准备：

```bash
.venv/bin/python scripts/setup_query_model.py
```

然后分别打开两个终端。

终端 1：

```bash
outputs/query_quality_runtime/venv311/bin/python scripts/local_qa_server.py
```

终端 2：

```bash
.venv/bin/python scripts/run_query_app.py --port 8517
```

模型服务健康检查：

```bash
curl http://127.0.0.1:8765/health
```

返回 `"status": "ready"` 后，页面侧栏会允许启用本地 Qwen。中文模式需要 Qwen 翻译展示的英文评论；英文模式保留英文原文。

### 7.3 Windows 上的限制

Windows 机器可以运行数据处理、BM25/FAISS、分类、离线标签、测试和 Streamlit 页面，但仓库当前的 `scripts/local_qa_server.py` 使用 `mlx_lm`，不能直接在 Windows 上运行。Windows 审查时可关闭本地 Qwen，使用程序化有据回答。

48 GB 内存足以运行其他 Qwen 后端，但如果要接 Ollama、llama.cpp 或 Transformers，需要另做一个与 `/health`、`/generate`、`/generate_stream` 协议兼容的本地服务适配；这不属于当前 Git 版本已经验证过的运行路径，不应在验收时假装它已经可用。

## 8. 推荐的验收问题

先用下面这些问题检查解析、约束筛选、细分检索、总体倾向和多方面排版：

1. 新加坡航空经济舱的腿部空间好不好？
2. 新加坡航空经济舱的腿部空间、靠背调节、座椅舒适度和座椅清洁度分别怎么样？
3. 新加坡航空经济舱餐食的质量、分量和品种分别怎么样？
4. 新加坡航空经济舱的餐食、性价比和地面服务分别怎么样？
5. 比较新加坡航空和阿联酋航空经济舱的餐食品种与选择，哪家更好？
6. 新加坡航空和 United Airlines 经济舱的电影与娱乐内容哪家更好？
7. 从新加坡飞伦敦的经济舱，哪家航司腿部空间评价最好？
8. 英国航空经济舱的登机口服务、行李服务和延误处理分别怎么样？
9. 阿联酋航空经济舱的娱乐内容、屏幕、Wi-Fi 和系统操作分别怎么样？
10. How are seat legroom, recline, comfort, and dirty seats in Singapore Airlines economy class?

检查时不要只看回答是否流畅，还要确认：

- 航司、舱位、出发地和目的地约束是否正确解析。
- 多个方面是否分段或分标签页显示。
- 结论方向是否依据全部直接匹配评论的正负面汇总，而不是只依据展示的几条原文。
- 正向、负向百分比与两类数量是否相符。
- 代表性证据是否真的讨论所问细分项。
- 回答中的 `[1]`、`[A1]` 等引用是否能对应页面原文。
- 原始评分是否明确写出所属方面、平均分、满分和样本数。
- 细分项没有独立评分时，回答是否避免拿上位方面评分冒充细分评分。
- 中文模式的界面和回答是否保持中文；英文模式是否保持英文。
- 数据截至 2019 年的限制是否表达清楚。

完整固定问题集位于 `data/eval/query_smoke_40_20261019.json`。已有全量知识库和离线标签后，可运行：

```bash
python scripts/run_query_smoke_suite.py
```

## 9. 发现问题时怎样反馈

每个问题最好单独记录，至少包含：

```text
Git 提交编号：git rev-parse HEAD 的输出
操作系统：例如 macOS 15 / Windows 11
Python 版本：python --version
是否启用本地 Qwen：是 / 否
是否存在 labels.parquet：是 / 否
完整问题：
页面解析出的航司、舱位、航线、方面和细分项：
实际回答：
期望回答或期望行为：
相关证据编号：
是否可以稳定复现：
错误堆栈或终端日志：
```

如果是回答质量问题，应同时指出是“检索证据不相关”“全量统计方向错误”“评分口径错误”“引用错误”“语言混用”还是“文字表达问题”。这样可以快速判断需要修改解析、检索、聚合、回答校验还是界面。

## 10. 不要上传或互相覆盖的内容

- 不要把 `data/raw/`、`data/processed/`、`index/`、`models/`、`outputs/` 强行提交到 Git。
- 不要提交 `.venv/`、Hugging Face 缓存、系统临时文件或个人绝对路径。
- 不要修改或覆盖冻结的 `data/eval/gold_human_frozen_1000_20261019_v1.csv`。
- gold 如需修订，应另建 v2 并记录变化，不能静默覆盖 v1。
- 不要用 gold 标签训练、调参或选择模型后，再把同一份 gold 的结果描述成独立测试成绩。
- 修改代码前先新建分支；确认测试通过后再提交，以便审查和回退。

组员只需检查问题时，推荐流程是：克隆 `main` → 核对提交编号 → 建虚拟环境 → 跑测试 → 查看已有实验结果。需要实际操作页面时，再继续下载数据、重建知识库、检索索引、分类权重和离线标签。
